# PÉRFECT TON — прототип сайта (v2, по реальному брифу)

Салон красоты в Раменском: ногтевой сервис, ресницы, брови, солярий.
15 лет на рынке, 8 мастеров. Структура и тексты собраны по брифу
Александра (рекламная стратегия) и анкете Дианы — не выдуманы.

8 разделов отдельными вкладками:

| Файл | Вкладка |
|---|---|
| `index.html` | Главная |
| `about.html` | О салоне |
| `services.html` | Услуги (ногти / ресницы / брови / солярий) |
| `masters.html` | Мастера |
| `gallery.html` | Галерея |
| `reviews.html` | Отзывы |
| `promo.html` | Акции |
| `contacts.html` | Контакты и запись |

Стили — `diana.css`, скрипты — `diana.js` (мобильное меню, подсветка вкладки).
Дизайн не менялся с v1: тёмная шоколадная палитра из брендбука
(`#312322` / `#aa998a` / `#ffffff`), шрифт Jost, референс по духу —
prive7.com. Изменился только состав страниц и текст.

## Что изменилось относительно первой версии

- Раздел «Подология» стал частью «Услуг» (один из трёх пунктов ногтевого
  сервиса), не отдельной страницей — салон работает по 4 направлениям
  одинаково, не только по ногтям.
- Убран отдельный «Прайс» — цены существуют только в YCLIENTS, кнопки
  записи по всему сайту ведут туда напрямую.
- Добавлены «Мастера» (8 человек в команде) и «Акции» (отмечены в анкете
  как важные, сейчас пустой раздел-заготовка).
- Главное действие на сайте — **онлайн-запись через YCLIENTS**
  (100% ответа в анкете), не форма обратной связи.
- Адрес, ориентиры, режим работы (9:00–21:00), источник отзывов
  (Яндекс.Карты) — реальные данные из брифа.

## Интеграции

| Что | Как | Кто обновляет |
|---|---|---|
| Отзывы | **свои данные, своя вёрстка** — `data/reviews.json` + рендер в `diana.js`. Без iframe | обновляются сами раз в неделю |
| Карта | виджет Яндекс Карт (`map-widget`), `contacts.html` — единственный оставшийся iframe | — |
| Онлайн-запись | YCLIENTS в модальном окне поверх сайта (`diana.js`), без ухода со страницы | Диана в YCLIENTS |
| Услуги и цены | ведут в YCLIENTS — отдельного прайса на сайте нет | Диана в YCLIENTS |
| Акции / новости | **не подключены автоматически** | см. ниже |

Модалка записи: любая ссылка на `yclients.com` перехватывается в `diana.js`
и открывается во всплывающем окне. Отдельной разметки на страницах не нужно —
достаточно поставить обычную ссылку. Закрытие — крестик, клик по фону, Escape.

Скорость: YCLIENTS — тяжёлое приложение и на холодную стартует несколько
секунд, поэтому рамка **прогревается заранее** — при наведении на любую
кнопку записи, а если наведения не было, в простое после загрузки страницы.
К моменту клика окно обычно уже готово. Пока идёт загрузка, поверх рамки
крутится индикатор — вместо белого пятна, как было.

Важное ограничение: понять из страницы, загрузился виджет или встраивание
запрещено, **невозможно** — в обоих случаях iframe сообщает «load», а
`contentDocument` равен `null`. Поэтому автоопределения нет: ссылка
«В новой вкладке» видна в шапке окна всегда, и через 6 секунд после открытия
внизу появляется подсказка «Не открылось? Открыть запись в новой вкладке».
Если окажется, что YCLIENTS запрещает встраивание, правильное решение —
взять официальный код виджета в кабинете YCLIENTS либо сделать кнопки
обычными ссылками в новую вкладку (убрать перехват в `diana.js`).

### Отзывы: как это устроено

Iframe-виджет Яндекса выбросили: он открывался как «Сайт yandex.ru заблокирован»
и в любом случае тянул чужой интерфейс в наш дизайн. Вместо него:

1. `scripts/fetch_yandex_reviews.py` забирает отзывы со страницы организации
   и складывает в `site/diana/data/reviews.json`.
2. `.github/workflows/yandex-reviews.yml` запускает его **раз в неделю**
   (понедельник, 07:00 МСК) и коммитит файл, если что-то изменилось.
   Коммит в `site/**` сам поднимает пересборку Pages.
3. Аватарки авторов **скачиваются к себе** в `data/avatars/` (68×68, ~120 КБ
   на всех) — чтобы не зависеть от доступности Яндекса у посетителя. Если
   аватарки нет или файл не загрузился, показывается кружок с инициалом.
   Имя файла считается от автора и текста отзыва, а не от ссылки на картинку:
   адреса у Яндекса меняются от запроса к запросу, и привязка к ним
   заставляла перекачивать все аватарки каждый прогон. Уже скачанное
   повторно не качается, выпавшее из ленты — удаляется.
4. `diana.js` читает JSON и рисует карточки в стилистике сайта: рейтинг,
   звёзды бежевым, «читать полностью» для длинных отзывов, строка
   «Источник — Яндекс Карты. Обновлено: …». Имя автора — ссылка на блок
   отзывов салона на Картах, в шапке рейтинга кнопка «Смотреть на Яндекс
   Картах»: видно, что отзывы настоящие, первоисточник в один клик.

Блок ставится одним атрибутом, разметка не нужна:

```html
<div data-reviews></div>                                <!-- все отзывы + сводка -->
<div data-reviews data-limit="3" data-summary="off"></div>  <!-- тизер на главной -->
```

### Перенос на другой хостинг

Система состоит из двух независимых частей, и переносятся они по-разному:

**Сайт** — чистая статика (`site/diana/`: HTML, CSS, JS, `data/`). Копируется
на любой хостинг обычным FTP. Ни Python, ни базы, ни Node не нужно.

**Сборщик отзывов** — обычный Python-скрипт, привязки к GitHub в нём нет.
К GitHub привязан только планировщик — файл workflow на 60 строк. Варианты
после переезда:

1. **Сбор оставить на GitHub, сайт держать на хостинге** (проще всего).
   GitHub раз в неделю собирает `reviews.json` и аватарки, после чего
   workflow дополнительно заливает папку `data/` на хостинг — в проекте уже
   есть `deploy/deploy.py` для Majordomo, его можно вызвать тем же шагом.
   Репозиторий при этом остаётся как «мотор», сайт живёт на своём домене.
2. **Перенести всё на хостинг** — только если там есть cron, Python 3
   и возможность поставить Chromium. Последнее — главное ограничение:
   рабочие данные даёт браузерный путь (в логе «страница организации»),
   лёгкий HTTP-запрос к странице виджета отзывы не отдаёт. На обычном
   shared-хостинге Chromium обычно поставить нельзя.
3. **Запускать вручную** раз в месяц со своего компьютера и заливать
   `data/` на хостинг. Скрипт работает локально: `python3
   scripts/fetch_yandex_reviews.py`. Вариант «на крайний случай», но рабочий.

**Ограничения, о которых нужно знать.** Публичного API отзывов у Яндекса нет,
поэтому скрипт разбирает вёрстку страницы. Отсюда два риска: Яндекс меняет
вёрстку (правятся селекторы в начале скрипта) и Яндекс показывает капчу
IP-адресам облачных раннеров. Скрипт написан так, что при любой неудаче
**не трогает прошлые данные** — сайт продолжает показывать последние
успешно собранные отзывы, а в Actions появляется предупреждение.
Резервный путь без автоматики: сохранить страницу отзывов из браузера и

```
python3 scripts/fetch_yandex_reviews.py --html сохранённая-страница.html
```

Первый боевой сбор прошёл 20.08.2026: собрано 24 отзыва, рейтинг 5,0,
всего на Картах 132 отзыва. Если данных нет (первый запуск, пустой файл),
блок показывает аккуратную заглушку со ссылкой на Карты — выдуманные отзывы
не публикуем никогда.

Отзывы сортируются по дате, свежие первыми: Яндекс отдаёт их в своём
порядке (не хронологическом), поэтому даты разбираются функцией `date_key`
(«13 августа 2025», «16 июня» — без года считается текущий) и уже
отсортированный список обрезается до 24. Что не разобралось — уходит в конец.

Три вещи, вскрывшиеся на первых прогонах и уже учтённые в скрипте:
селекторы страницы организации отличались от ожидаемых (лечится
диагностикой `--debug`, она печатает в лог реальную структуру), а длинные
отзывы Яндекс прячет под «Ещё» и отдаёт обрезанными на ~300 символах —
поэтому перед сбором скрипт раскрывает все свёрнутые тексты.

### Почему акции не тянутся из Яндекса

У Яндекса есть официальные виджеты только для отзывов и карты. Для постов
(вкладка «Новости» в карточке) и для списка услуг публичного виджета или API
нет — забрать их автоматически на статический сайт нельзя. Варианты, из
которых нужно выбрать с Дианой:

1. **Оставить как есть** — кнопка «Новости на Яндекс Картах» ведёт в карточку.
2. **Дублировать в Telegram-канал** — у Telegram есть встраиваемые виджеты
   постов, лента на сайте будет обновляться сама.
3. **Таблица Google Sheets** — Диана заполняет строки (картинка + текст),
   сайт читает их как ленту. Редактировать может кто угодно, без разработчика.

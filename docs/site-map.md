**Видеовиджет** — прямоугольник 9:16 слева внизу. Стили в конце
`site.css` (блок «Видеовиджет»), логика в конце `site.js`. Что нельзя
ломать:

1. видео (`assets/ash-video-widget-lite.mp4`, 963 КБ, 360×640, faststart)
   начинает грузиться **после `window.load`**, а не вместе со страницей;
2. виджет всплывает только по `canplaythrough` (и не раньше
   `readyState >= 2`) — иначе в углу мигает чёрный прямоугольник;
3. ролик играет **один раз**, потом виджет уезжает и возвращается
   через 20 с (каждый следующий заход ждёт на 20 с дольше, максимум
   90 с). `loop` намеренно убран. Показ виджета одноразовый на
   загрузку страницы (`vwShown`): перемотка в начало заново вызывает
   `canplaythrough`, и без флага виджет выскакивал обратно сразу;
4. звук пробуем включить сразу (`vwPlayLoud`): если браузер
   отклоняет запуск со звуком — откатываемся на немой показ, а звук
   включаем при первом же касании страницы (`vwUnlock`, один раз,
   и только если человек не выключил его сам). Раньше было — автозапуск со звуком браузеры
   запрещают; звук включается кнопкой «Звук выкл/вкл»;
5. **размер один и увеличить нельзя** — исходник сжат, крупнее выглядит
   плохо. Поэтому нет `controls`, стоят `controlslist="nodownload
   nofullscreen noplaybackrate noremoteplayback"`,
   `disablepictureinpicture`, перехвачены правая кнопка, `dragstart`
   и двойной клик. Окна с крупным видео больше нет вообще;
6. кнопка «Оставить заявку» (`.vw-cta`, ссылка на `#quiz`) всплывает
   на секунде из `data-cta-at` в разметке — там, где о заявке говорят
   в ролике, — и уезжает вместе с виджетом. Пока открыт квиз, ролик
   на паузе;
7. клик по кадру = пауза/продолжить. Показом зелёной кнопки
   управляет только JS (класс `is-touched`): CSS `:hover` убран
   намеренно — он залипал после клика и после тапа, кнопка висела
   на лице. Подпись «Включить звук» видна всегда.

Обложка (`ash-video-widget-poster.jpg/.webp`) — кадр 15.6 с, спокойное лицо.

**Блок «Ответы на вопросы».** Снимок Александра — фон всей полосы во
всю ширину экрана: `faq-sasha-2026-wide.jpg` (1920×750).
**`background-size:100% auto`, не `cover`** — cover тянул кадр по высоте
блока и на 1440px увеличивал его на 22%, лицо выходило мыльным. Сейчас
на 1920px кадр показывается один в один, на меньших — с уменьшением;
высота полосы задана той же пропорцией (39.06vw).
**`padding-top` блока — clamp(150px,17vw,300px), не больше:** текст
должен стоять там же, где стоял, а блок — умещаться в один экран.
Один раз его увеличили ради «полного кадра» — блок разъехался,
пришлось возвращать. На телефоне тот же
файл узким кадром (`background-size:250% auto`).
Стык с предыдущим блоком: полоса `.faq::before` уводит фон страницы в
цвет верхнего края снимка, а сам кадр проявляется на `--faq-edge`

с 42-го пикселя), поэтому лицо не затемняется, а канта нет. Полоса примыкает к соседним блокам
встык: `.faq{margin:calc(-1*var(--gap)) auto}` съедает флекс-зазор
`.page`, `.faq + .closer{margin-top:0}` убирает воздух снизу.

## Проверка перед push

Локально: `cd site && python3 -m http.server 8899` (в фоне через
`nohup ... & disown`). Playwright: `executable_path=
"/opt/pw-browsers/chromium-1194/chrome-linux/chrome"`.

Минимум — ширины 360/390/560/900/1280/1440/1920: `hscroll=false`, нет
ошибок в консоли (`page.on("pageerror")`), нет 404 (`page.on("response")`).

**Для рефакторинга и любых правок «не должно измениться визуально» —
пиксель-диф вместо просмотра скриншотов глазами** (это и есть главная
экономия токенов):

1. `git archive HEAD site | tar -x -C /tmp/before` и поднять на 8898;
2. текущую версию — на 8899;
3. снять одни и те же секции в обоих и сравнить `PIL.ImageChops.difference`;
4. смотреть глазами только то, где `diffpx > 0`.

Так проверены и вынос CSS/JS, и переформатирование слайдов: 20 состояний
кейсов на двух ширинах — 0 отличающихся пикселей, без единого просмотра
картинки.

## Экономия токенов

Дорого не столько код, сколько **картинки в контексте**: скриншот стоит как
несколько страниц текста. Отсюда правила:

1. Один блок работы — один чат. Старые скриншоты утяжеляют каждый шаг.
2. Правки присылать списком, а не по одной.
3. Проверять пиксель-дифом (см. выше), а не просмотром скриншотов.
4. Открывать файлы точечно по этой карте, а не целиком.
5. Один скриншот всей секции лучше пяти скриншотов фрагментов.
6. Не перечитывать одно и то же изображение, если состояние не менялось.
7. Текст вёрстать живым HTML, а не встраивать в растр — иначе любая
   правка слова превращается в пиксельный подбор шрифта.

## Git и деплой

Живой сайт: `https://alina3500-2-arch.github.io/project-s-sashey/`
Превью ПК с телефона: `.../pc.html`

Деплоит `.github/workflows/pages.yml` при пуше в `main`, публикует папку
`site/` **как корень** — поэтому в URL нет `/site/`.

Правки идут из нескольких инструментов (этот чат и Codex). Перед push:

```
git fetch origin main && git log --oneline -1 origin/main
```

Есть чужие коммиты — не пушить и не мерджить молча: показать пользователю
`git show <коммит> --stat` и спросить. Force push — никогда.

**Осторожно: локальная ветка `main` в некоторых сессиях — это вообще другой
проект (нет общей истории с `origin/main`, `git merge` падает с
`unrelated histories`).** Проверять `git log --oneline -1 main` перед любой
работой с ней. Рабочий способ — не трогать локальный `main`, а пушить
свою ветку прямо в удалённый:

```
git merge-base --is-ancestor origin/main HEAD && \
git push origin <моя-ветка>:main
```

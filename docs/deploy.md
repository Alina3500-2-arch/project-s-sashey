# Деплой сайта на ashpartners.ru (Majordomo)

## Почему не напрямую из чата

Сессия Claude Code работает в изолированном контейнере: весь исходящий трафик
идёт через шлюз, который пропускает только HTTP/HTTPS на разрешённые хосты.

Проверено:
- порт 21 (FTP) и 22 (SSH/SFTP) — не проходят вообще, таймаут на уровне TCP;
- `ashpartners.ru` по 443 — шлюз отвечает
  `403 Host not in allowlist: ashpartners.ru`.

Это ограничение среды, а не хостинга и не прав доступа. Дополнительные пароли
ситуацию не меняют. Поэтому файлы уезжают на хостинг из GitHub Actions —
у раннеров GitHub сеть не ограничена.

## Схема

```
Claude пушит в ветку  →  GitHub Actions  →  FTP  →  Majordomo  →  ashpartners.ru
```

Workflow: `.github/workflows/deploy.yml`. Заливает содержимое папки `site/`.
Срабатывает на push в `main` и `claude/**`, когда менялось что-то в `site/`,
плюс вручную кнопкой Run workflow.

## Что нужно сделать один раз

В GitHub: **Settings → Secrets and variables → Actions → New repository secret**.
Четыре секрета:

| Имя | Значение |
|---|---|
| `FTP_SERVER` | `ftp.majordomo.ru` или IP сервера из панели |
| `FTP_USERNAME` | FTP-пользователь вида `fXXXXXX_имя` |
| `FTP_PASSWORD` | пароль этого FTP-пользователя |
| `FTP_SERVER_DIR` | путь до корня сайта, **со слешем на конце** |

`FTP_SERVER_DIR` посмотреть в панели Majordomo → раздел с сайтами → у
`ashpartners.ru` указана корневая директория. Обычно это что-то вида
`/ashpartners.ru/www/` относительно домашней папки FTP-пользователя. Если
после первого деплоя файлы окажутся не там — поменять только этот секрет,
перезапустить workflow.

Пароли живут только в секретах GitHub. В репозиторий они не коммитятся.

## Проверка

1. GitHub → вкладка **Actions** → workflow «Deploy to hosting» → Run workflow.
2. В логе шага «Upload site/ via FTP» видно список отправленных файлов.
3. Открыть `https://ashpartners.ru/` — должен быть первый экран.

При первом запуске уезжают все файлы, дальше — только изменённые: состояние
синхронизации хранится на сервере в `.ftp-deploy-sync-state.json`.

## Альтернатива: прямой доступ у Claude

Если нужно, чтобы Claude заливал файлы мгновенно, без прогона через CI:

1. Добавить `ashpartners.ru` в network egress settings окружения
   (документация: https://code.claude.com/docs/en/claude-code-on-the-web).
2. Один раз вручную положить на хостинг небольшой `deploy.php` с секретным
   токеном, который принимает файлы по HTTPS.

После этого Claude пишет файлы напрямую. Важно понимать цену: такой файл —
это точка входа на запись в сайт, защищённая только токеном. Её нужно удалить,
когда закончим активную работу.

## Безопасность

Пароль FTP пересылался открытым текстом в чате — после настройки секретов его
стоит сменить в панели Majordomo и обновить `FTP_PASSWORD` в GitHub.

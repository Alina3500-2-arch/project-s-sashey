# Как мы работаем над сайтом

Схема на два места: правки с телефона в дороге, заливка на домен вечером
с компьютера.

```
телефон (в дороге)          компьютер (вечером)
    │                             │
    ├─ говорю правки Claude       │
    ├─ Claude коммитит в GitHub ──┤
    ├─ смотрю превью в браузере   │
    │                             ├─ двойной клик по deploy
    │                             └─ сайт уезжает на ashpartners.ru
```

Единственный источник правды — репозиторий на GitHub. Всё, что видно на
превью и на домене, приезжает оттуда.

## В дороге, с телефона

1. Пишете, что поменять.
2. Claude правит `site/index.html` и пушит в GitHub.
3. Через минуту открываете **адрес превью** в обычном браузере и смотрите.

Ничего заливать не нужно. Правок может быть сколько угодно — каждая
попадает в историю, любую можно откатить.

Превью — обычная страница по https, без логинов и приложений.

## Вечером, за компьютером

Один раз при первой настройке:

1. Склонировать репозиторий (или скачать zip и распаковать).
2. Скопировать `deploy/.env.example` рядом и назвать `.env`
   (получится `deploy/.env`).
3. Вписать туда четыре строки: адрес FTP, логин, пароль, папку сайта.
   Всё это есть в панели Majordomo. Папка сайта указана в карточке домена.

Дальше, каждый раз:

- **Mac** — двойной клик по `deploy/deploy.command`
- **Windows** — двойной клик по `deploy/deploy.bat`

Скрипт сам заберёт свежую версию из GitHub и зальёт папку `site/` на
хостинг. В окне будет видно, какие файлы отправлены. В конце — «Готово».

Нужен установленный Python 3. На Mac он уже есть. На Windows ставится с
python.org, при установке отметить галочку «Add Python to PATH».

### Если что-то пошло не так

| Что в окне | Что делать |
|---|---|
| `Не найден файл с доступами` | не создан `deploy/.env`, см. шаг 2 |
| `Нет такой папки на сервере` | неверный `FTP_DIR`, сверить с панелью |
| `Хостинг отказал` | неверный логин или пароль |
| `Не получилось соединиться` | проверить интернет и `FTP_HOST` |

## Почему заливка именно с компьютера

Облачная сессия Claude работает в изолированном контейнере: наружу
пропускается только HTTP/HTTPS на разрешённые адреса, порты FTP и SSH
закрыты. Это ограничение среды, а не прав доступа — никакой пароль его не
снимает. На вашем компьютере таких ограничений нет, поэтому FTP там
работает как в обычной программе.

Пароли лежат только в `deploy/.env` на вашем компьютере. Этот файл в
`.gitignore` и на GitHub не уезжает.

## Если захочется совсем без компьютера

В репозитории лежит `.github/workflows/deploy.yml` — заливка силами
GitHub, на каждый пуш. Чтобы включить, надо один раз добавить четыре
секрета в настройках репозитория (см. `docs/deploy.md`). Тогда домен
будет обновляться сам, и вечерний шаг не понадобится.

Пока эта схема выключена: она полезна, когда правки уже согласованы, а на
этапе черновиков удобнее, чтобы на домен попадало только то, что вы сами
решили отправить.
